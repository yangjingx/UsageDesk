# UsageDesk 0.2.0 appearance plan

## Problem

The 0.1.3 provider popover paints its own dark blue background while macOS chooses dark text in Light Mode. The cards also hard-code white labels and dark gradients, so the app never follows the system appearance.

## Design rules

1. Let system appearance choose foreground and surface colors. Use primary/secondary semantic labels and a window background material for the card. OpenAI's general identity favors restrained neutral surfaces, while the current official Codex app icon uses blue-violet. Use a small indigo accent for Codex, neutral gray for its secondary meter, and DeepSeek blue for its own card. Do not use the old mint/teal palette.
2. Let SwiftUI/AppKit draw the provider popover and ordinary settings controls. Remove the fixed popover fill and text colors. A popover is a transient navigation control; on macOS 26 and later, the system can give it Liquid Glass automatically.
3. Apply glass only to a small number of floating controls, if it improves the hierarchy. Do not turn the balance or quota content into glass. Respect Reduce Transparency and Reduce Motion.
4. Keep the existing 330-point card width, drag-from-empty-area behavior, menu bar preferences, data sources, Keychain storage, and released app untouched while testing.
5. Use the user-approved double-ring mark for the app icon. The two arcs suggest remaining capacity for Codex and DeepSeek; graphite and blue distinguish them without borrowing either provider's logo. Avoid simulated glass highlights baked into pixels. Generate a static icon compatible with macOS 15 and later; a layered Icon Composer source can be added when that tool is available.
6. Remove the old mint-colored OpenAI-like mark. OpenAI's guidelines prohibit adding colors to its Blossom and prohibit using it as this app's own branding. Use a generic code glyph for Codex until an approved official provider asset can be used without alteration. The UsageDesk app icon remains independent of OpenAI's marks.

## Acceptance checks

- Light and Dark Mode: Codex and DeepSeek cards, provider popover, gear settings, meters, links, and disabled controls remain legible.
- Both layouts and both languages render without clipping; switching cards and dragging still work.
- Reduce Transparency uses an opaque surface; Reduce Motion removes decorative transitions.
- Package a separate local 0.2.0 preview, test it, and publish only after the user explicitly approves the release.

## Local verification

- Compiled with the macOS 26.5 SDK targeting macOS 15; the signed preview bundle passes `codesign --verify --strict`.
- Visually checked Light and Dark Mode in running test apps with sample Codex and DeepSeek data. The native title popover has readable text in both appearances; the English vertical layout does not clip.
- Tested dragging from an empty area. The original window-relative calculation produced a large jump; the revised screen-coordinate calculation moved the window without that initial jump. The automation reports coordinates relative to the moving window, so physical pointer tracking still needs a mouse or trackpad acceptance test.
- After approval, the 0.2.0 build was installed locally. The final balance-row alignment and double-ring icon were checked in the running app before publication.
