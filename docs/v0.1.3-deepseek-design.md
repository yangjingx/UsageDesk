# UsageDesk v0.1.3 · DeepSeek API 接入设计草案

状态：设计阶段。本文不代表 v0.1.3 已实现或发布。

## 结论与边界

v0.1.3 接入 **DeepSeek 开放平台 API**，显示账户余额。它不把余额称为“剩余 Token”，也不把 DeepSeek 网页聊天的使用情况与 API 余额混为一谈。DeepSeek 官方 `GET /user/balance` 返回是否可用于 API 调用、币种、可用总余额、赠金余额和充值余额；单次模型响应的 `usage` 只描述该次调用。调研所见的官方文档没有提供可用 API Key 读取全账户累计 Token、按模型 Token 明细或五小时/每周窗口的公开接口。[官方余额接口](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/) · [官方单次 Token 统计](https://api-docs.deepseek.com/api/create-response/)

GitHub 上的 [Coding Usage Bar](https://github.com/hanzhangzzz/coding-usage-bar) 和 [QuotaBar](https://github.com/QuotaBar/QuotaBar) 都把 DeepSeek 作为余额型数据源；[CodexBar 的 DeepSeek 说明](https://github.com/steipete/CodexBar/blob/main/docs/deepseek.md)指出详细用量依赖平台网页会话，API Key 无法直接访问这些内部接口。DeepSeek 社区中也有[请求公开汇总用量接口的问题](https://github.com/deepseek-ai/awesome-deepseek-integration/issues/654)。v0.1.3 只使用公开 API Key 接口，不导入浏览器 Cookie、网页会话令牌或平台内部接口。

## 用户界面

- 设置中提供“卡片布局 / Card layout”二选一：**切换卡片 / Switch cards** 与 **垂直展开 / Show both vertically**。使用系统 SwiftUI 分段选择器，并将选择保存在本机设置中。[Apple 分段选择器](https://developer.apple.com/documentation/swiftui/pickerstyle/segmented) · [Tally 多账户布局参考](https://github.com/jettoai/tally)
- “切换卡片”保持当前紧凑尺寸，在卡片顶部切换 **Codex / DeepSeek**；记住上次选中的服务。“垂直展开”在同一个窗口中上下显示两块完整的服务卡片，各自保留标题、数据更新时间、刷新和设置入口。默认沿用现有紧凑体验，用户可随时改为同时显示。
- 两种布局下，已启用的 Codex 和 DeepSeek 都按各自的刷新计划运行；切换画面不会暂停另一个服务的数据更新。未设置 DeepSeek API Key 时，展开模式显示连接提示，而不是虚构余额。
- 切换布局时固定窗口左上角并调整高度，避免卡片跳位；窗口高度按内容计算，超过当前显示器可见区域时限制高度并允许内部滚动。使用 AppKit 的窗口尺寸接口，不通过销毁并重建窗口切换布局。[Apple 窗口尺寸接口](https://developer.apple.com/documentation/appkit/nswindow/setframe%28_%3Adisplay%3Aanimate%3A%29)
- DeepSeek 卡片主数字为带币种的可用余额，例如 `¥110.00`；下方分列“赠金 ¥10.00 / 充值 ¥100.00”，并显示“可用于 API 调用”或“余额不可用”及最后更新时间。CNY 与 USD 分开显示，绝不跨币种相加。
- 未配置密钥时显示“连接 DeepSeek API”，引导到设置窗口。设置提供密钥输入、连接测试、更换和删除；密钥始终掩码显示。
- DeepSeek 不显示五小时/每周进度条或“剩余 Token 百分比”。若未来加入用户自行设定的预算，必须明确标注“自设预算”，不能写成官方额度。
- 所有新文案提供简体中文和英文，默认跟随系统语言，设置中允许手动切换。现有 Codex 文案也同步迁移到本地化资源。

## 数据与结构

1. 将当前仅面向 Codex 的 `UsageSnapshot` 拆为服务独立的数据：`CodexQuotaSnapshot` 和 `DeepSeekBalanceSnapshot`。展示层使用带类型的 `ProviderSnapshot`，避免把金额和百分比放在同一个字段中。
2. 保留旧 `usage.json` 读取路径并迁移现有 Codex 快照；DeepSeek 快照单独保存于当前用户的 Application Support 目录。保留每个服务自己的更新时间和错误状态，失败时可显示带原时间戳的上次成功值。
3. 通过固定的 `https://api.deepseek.com/user/balance` 发起 `GET` 请求，使用用户输入的 API Key 作为 Bearer 凭据。解析十进制字符串金额，处理 `balance_infos` 多币种数组与 `is_available`。绝不把 Key 写进 URL、日志、快照、安装包或 Git 仓库。
4. API Key 存在 macOS Keychain，使用 Security framework 的通用密码项；网络请求使用 `URLSessionConfiguration.ephemeral`，限定 HTTPS 固定主机并拒绝把认证头带到重定向目标。[Apple Keychain](https://developer.apple.com/documentation/security/adding-a-password-to-the-keychain) · [Apple 临时会话](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/ephemeral)
5. Codex 保持现有本机读取方式。DeepSeek 默认每 60 秒刷新，可独立设置间隔；失败或限流时指数退避。10 秒 Codex 设置不自动套用到 DeepSeek。60 秒是产品默认值，并非官方保证的数据更新频率。

## 现有代码改造的先决条件

当前卡片的拖动逻辑使用固定坐标排除刷新、编辑和链接。新增服务切换、垂直布局和双语文案后，控件位置与窗口高度都会变化，因此实现界面前必须改为基于实际控件区域的命中测试，或使用明确的可拖动背景视图，避免再次出现按钮遮挡或无法拖动。实现后在中文和英文两种界面中分别实测拖动、刷新、编辑、服务切换、布局切换和菜单栏操作。

## v0.1.3 验收

- 无密钥时 Codex 功能与旧快照不受影响；设置 DeepSeek Key 后可读取真实余额，删除 Key 后停止请求。
- 解析 CNY、USD、多币种、零余额、`is_available=false`、非法金额、认证失败、网络超时和服务端错误。
- 更新应用后 Keychain 凭据仍可读取；若当前临时签名方式导致钥匙串权限提示，发布前解决或明确说明。
- 在中文和英文两种语言下验证界面布局与所有点击区；真实拖动应使窗口坐标变化且松开后保存。除自动化坐标检查外，还要人工观察是否跟手、是否闪烁。
- 切换卡片与垂直展开模式之间往返后，两边数据和选中服务不丢失；展开高度不会越出可见屏幕，拖动和按钮在两种布局中都正常工作，布局切换没有闪烁。
- 发布前审查安装包和源码，确认没有 Cookie、Token、API Key 或用户余额样本；Release 更新日志继续中英双语。
